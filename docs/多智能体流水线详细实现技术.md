## 二、智能体基类 AgentBase（模板方法模式）

源码：[ai/agents/base.py](../ai/agents/base.py)

### 2.1 依赖注入容器 AgentDeps

[base.py:15](../ai/agents/base.py#L15) — 把所有后端组件装进一个 dataclass，运行时透传给工具函数：

```python
@dataclass
class AgentDeps:
    knowledge: Any = None         # KnowledgePack：分层知识文档注入
    asset_index: Any = None       # AssetIndex：UE 资产关键词搜索
    experience_bank: Any = None   # ExperienceBank：SQLite 经验库
    retriever: Any = None         # ExperienceRetriever：四因子检索
    pattern_library: Any = None  # PatternLibrary：模式库
    validator: Any = None         # 复用为 UE Content 目录路径（资产磁盘校验）
```

所有字段默认 `None`，允许按需注入（测试时只传 `knowledge` 即可）。所有阶段共享**同一个** `AgentDeps` 实例，由 `init_deps()` 一次性装配。

### 2.2 模板方法：固化创建流程

[base.py:65](../ai/agents/base.py#L65) `build()` 把"创建智能体"的公共流程锁死，子类只填三个钩子：

```python
def build(self) -> Agent:
    if self._agent is not None:            # 懒加载缓存，避免重复构建
        return self._agent
    model = self._create_model()          # 1. OpenAIChatModel
    self._agent = Agent(
        model,
        deps_type=AgentDeps,              # 2. 声明依赖类型（工具 ctx.deps 的类型）
        retries=self._retries,            # 3. 输出无效时重试次数（默认3）
        system_prompt=self._system_prompt(),  # 4. 子类提供提示词
        output_type=self._output_type(),      # 5. 子类提供输出 Pydantic 模型
    )
    self._register_tools(self._agent)      # 6. 子类注册 @agent.tool
    return self._agent
```

### 2.3 统一执行入口

[base.py:87](../ai/agents/base.py#L87) `run()` 封装 `agent.run()`，**自动透传 deps**，避免调用者忘记传依赖导致 `ctx.deps` 为 None：

```python
async def run(self, user_prompt: str) -> Any:
    agent = self.build()
    return await agent.run(user_prompt, deps=self._deps)
```

### 2.4 三个抽象钩子

```python
def _output_type(self) -> Any:           # 子类覆盖指定结构化输出
    return None
def _system_prompt(self) -> str:         # 子类必须实现
    raise NotImplementedError
def _register_tools(self, agent: Agent): # 子类必须实现
    raise NotImplementedError
```

> **设计要点**：模板方法模式让"如何组装一个 Agent"的流程固化在基类，子类只声明差异（提示词/输出类型/工具），消除重复代码。

### 3.1 NarrativeEnricherAgent（Stage 0，可选）

源码：[ai/agents/narrative_enricher.py](../ai/agents/narrative_enricher.py)

**职责**：把简短描述扩写为富有画面感的叙事文本，供 Stage 1 更精准提取。**纯 LLM，零工具**。

```python

    def _system_prompt(self):

    def _register_tools(self, agent):
        pass                # 纯 LLM 生成，不调用任何工具
```

**关键边界设计**（[narrative_enricher.py:7-11](../ai/agents/narrative_enricher.py#L7-L11)）：
- ✅ 只描述**定性空间关系**（方位/流向/疏密）
- ❌ 不写**定量参数**（坐标/尺寸/网格）

原因：Stage 0 缺少场景尺寸/资产列表/坐标系等定量决策所需信息，在"信息真空"中做空间决策必然产生与 Stage 2 实际结果矛盾的参数。

**强制规则**：房屋必须写明数量（"十余栋农舍"而非"有房屋"）；远景必须有山脉背景（除非用户明确说平原/沙漠）。

### 3.4 QualityGuardAgent（Stage 3）— 闭包计数器防死循环

源码：[ai/agents/quality_guard.py](../ai/agents/quality_guard.py)

**职责**：字段校验 + 资产路径校验 → 有错则 LLM 修复（可调 `search_assets` 找替代路径）→ 程序化强制最多 3 轮 → 输出 `ValidationReport`。

**核心反例修复 — 程序化轮次强制**（[quality_guard.py:69-97](../ai/agents/quality_guard.py#L69-L97)）：

```python
def _register_tools(self, agent):
    _MAX_ROUNDS = 3
    _round_counter = [0]          # 闭包可变变量（list 包装实现跨调用修改）

    @agent.tool
    async def validate_all(ctx, scene_json) -> dict:
        _round_counter[0] += 1
        current_round = _round_counter[0]
        # 超过上限 → 返回信号强制 LLM 停止
        if current_round > _MAX_ROUNDS:
            return {
                "round": current_round,
                "max_rounds": _MAX_ROUNDS,
                "signal": "MAX_ROUNDS_REACHED",
                "message": "已达到最大校验轮数(3)，请停止重试...",
            }
        # 正常校验：字段校验 + 资产磁盘存在性校验合并为一次
        field_result = validate_scene_core(scene)        # 字段完整性
        asset_errors = validate_assets_core(scene, content_dir)  # 资产路径
        return {
            "round": current_round,
            "field_errors": field_result.get("errors", []),
            "asset_errors": asset_errors,
            "is_valid": (len(field_result.get("errors", []))
                         + len(asset_errors)) == 0,
            ...
        }
```

> **关键设计教训**：原先"最多3轮"仅是系统提示词**文字约束**，LLM 可无视（实测无限重试 13 次）。改成闭包计数器后由**代码强制终止**——这是"不能只靠提示词约束 LLM 行为边界"的典型反例修复。

**资产修复策略**（[quality_guard.py:137-147](../ai/agents/quality_guard.py#L137-L147)）：`validate_all` 报告资产路径缺失时，LLM 可调用 `search_assets` 搜索替代路径，从返回结果选最匹配 `path` 替换，使资产修复率从 ~40% 提升到 ~85%。

**灵活性与约束的平衡**（[scene_json.py:1-8](../ai/models/scene_json.py#L1-L8)）：
- 复杂嵌套结构（height_pattern、weight_pattern、grid）用 `dict` 保持灵活，因为它们由 C++ 层解析或结构随场景类型变化，过度约束反而导致 LLM 输出校验失败。
- 默认值对齐 `build_scene.py` 源码默认值（如 `section_size_quads=63`、`scale=[100,100,100]`）。

**内置 Pydantic 校验器**（[scene_json.py:56-81](../ai/models/scene_json.py#L56-L81)）— `PlacementConfig.validate_asset_nonempty`：

```python
@model_validator(mode='after')
def validate_asset_nonempty(self) -> "PlacementConfig":
    """防止 LLM 生成空 asset 占位条目导致 UE 卡死。"""
    if self.type == "group":
        if not self.asset_prefix or not self.asset_prefix.strip():
            raise ValueError("group 类型必须填写非空 asset_prefix")
    elif self.type != "village":
        if not self.asset or not self.asset.strip():
            raise ValueError(f"{self.type} 类型必须填写非空 asset 路径"
                             f"— 空 asset 会导致 UE 编辑器卡死")
    return self
```

> 校验失败时 Pydantic 抛 `ValueError`，PydanticAI 自动重试（`retries=3`），将错误消息反馈给 LLM 要求修正输出——**模型校验即闭环反馈**。

## 五、工具系统

### 5.1 @agent.tool 装饰器机制

PydanticAI 把工具函数的**签名**（参数名 + 类型注解 + docstring）自动转成 JSON Schema 喂给 LLM。LLM 据此决定何时调用、传什么参数。

```python
@agent.tool
async def inject_knowledge(
    ctx: RunContext[AgentDeps],   # 第一个参数固定为上下文，LLM 不可见
    terrain_type: str,             # 以下参数 LLM 可见，会出现在 Schema
    has_water: bool,
    ...
) -> str:                          # 返回类型注解 → LLM 知道返回什么
    """注入分层知识文档。"""        # docstring → LLM 看到的工具说明
    ...
```

### 5.2 核心函数与工具装饰分离（可测试性）

所有工具采用**双层结构**：
- **核心函数**（`*_core`，位于 `ai/tools/`）：接收纯 Python 对象（dict/Stub），便于单元测试直接传入 mock。
- **Agent 工具**（`@agent.tool`，位于 `ai/agents/`）：接收 JSON 字符串（LLM 接口），内部调核心函数。

示例 — [asset_tools.py](../ai/tools/asset_tools.py)：

```python
def search_assets_core(asset_index, keywords, max_results=20):
    """核心函数：接收 AssetIndex 实例，返回 AssetEntry 列表。
    单测时可直接传入 Stub 对象。"""
    if asset_index is None:
        return []
    paths = asset_index.search(keywords, max_results=max_results)
    return [AssetEntry(path=p, ...) for p in paths]
```

```python
# Agent 工具层（json_builder.py 内）
@agent.tool
async def search_assets(ctx: RunContext[AgentDeps], keywords: list[str]):
    entries = search_assets_core(ctx.deps.asset_index, keywords)
    return [e.model_dump() for e in entries]   # 序列化为 dict 供 LLM 读取
```

## 六、依赖组件层

### 6.1 KnowledgePack — 分层知识注入 + 模板裁剪

源码：[ai/knowledge.py](../ai/knowledge.py)

**分层组装 system prompt**（[knowledge.py:185](../ai/knowledge.py#L185) `build_system_prompt`）：

| 层级 | 内容 | 注入策略 |
|------|------|---------|
| L1 | core.md 核心知识（~3KB） | 始终注入 |
| L2 | height_pattern.md / weight_pattern.md / placements.md / asset_guide.md | 按意图选择（有水→height_pattern，有草→weight_pattern...） |
| L2.5 | 高质量模板 JSON（few-shot 标杆） | 按 intent 关键词/地形匹配 |
| L3 | 资产路径列表 | 传空（由 LLM 调 search_assets 获取） |
| L4 | 经验 few-shot | 传空（由 ScenePlanner 在 blueprint.experience_refs 传递） |

> **L2.5 模板标杆是提升初次生成质量的关键**：AI 拿到一个已验证的完整 JSON 可模仿，而非仅靠字段表盲写。

**模板智能裁剪**（[knowledge.py:103-157](../ai/knowledge.py#L103-L157) `_trim_template`）— 超过 `_MAX_TEMPLATE_BYTES=15000` 的模板不直接排除，而是保留结构骨架、截断过长重复数组（如围栏 150 个实例 → 5 个）后再注入：

```python

for p in data.get("placements", []):
    instances = p.get("instances")
    if isinstance(instances, list) and len(instances) > self._TRIM_ARRAY_KEEP:
        p["instances"] = instances[:self._TRIM_ARRAY_KEEP]
        p["_note"] = "(原始 %d 个实例, 已裁剪为前 5 个作为结构参考)"
# height_pattern 中 hills/valleys/ridges/scatter 同理截断
```

**模板匹配规则**（[knowledge.py:21-37](../ai/knowledge.py#L21-L37)）— 按优先级排序：特定地形模式 > 特定资产关键词 > 水系 > 默认全地形。

### 6.2 AssetIndex — 关键词加权搜索

源码：[ai/asset_index.py](../ai/asset_index.py)

从 `config/asset_catalog.json` 构建，关键词命中加权打分（[asset_index.py:28-41](../ai/asset_index.py#L28-L41)）：

```python
def _match_score(self, asset, keywords):
    name = asset.get("name", "").lower()
    cat = asset.get("category", "").lower()
    sub = asset.get("subfolder", "").lower()
    score = 0
    for kw in keywords:
        kw_lower = kw.lower()
        if kw_lower in name: score += 3   # name 匹配权重最高
        if kw_lower in cat:  score += 2
        if kw_lower in sub:  score += 1
    return score
```

按分数降序、去重、截断 `max_results`。

### 6.3 ExperienceBank — SQLite + FTS5 全文检索

源码：[ai/experience_bank.py](../ai/experience_bank.py)

**表结构**（[experience_bank.py:31-47](../ai/experience_bank.py#L31-L47)）：主表 `experiences` + 虚拟表 `experiences_fts`（FTS5 全文索引 `keywords_text`）。

**FTS5 加速检索**（[experience_bank.py:81-113](../ai/experience_bank.py#L81-L113) `_find_similar`）— 先用 FTS5 `MATCH` 快速筛选关键词有重叠的候选（O(k)），再对候选集精确计算 Jaccard 相似度（避免全表扫描 O(n)）：

```python
safe_tokens = ['"' + kw.replace('"', '""') + '"' for kw in my_keywords]
query = " OR ".join(safe_tokens)   # 关键词 OR 连接
candidate_rows = self._conn.execute(
    "SELECT e.id, e.intent_json FROM experiences e "
    "JOIN experiences_fts f ON e.id = f.rowid "
    "WHERE experiences_fts MATCH ? ORDER BY rank", (query,)).fetchall()
```

**去重更新**（[experience_bank.py:136-157](../ai/experience_bank.py#L136-L157) `save`）：Jaccard ≥ 0.6 视为相似经验，更新而非新增；FTS5 索引同步删除旧+插入新。

**旧库迁移兼容**：检测 `keywords_text` 列是否存在，不存在则 `ALTER TABLE` 补加并回填；FTS5 索引为空时从主表回填。

### 6.4 ExperienceRetriever — 四因子评分 + MMR 多样性

源码：[ai/retriever.py](../ai/retriever.py)

**四因子加权评分**（[retriever.py:9-12](../ai/retriever.py#L9-L12)）：

```python
WEIGHT_KEYWORD_SIM = 0.65   # 关键词 Jaccard 相似度（主导因子）
WEIGHT_RECENCY     = 0.15   # 时效性：1/(1+天数)
WEIGHT_RELIABILITY = 0.20   # 可靠性：success/(total+1)
WEIGHT_DIVERSITY   = 0.10   # 多样性（MMR）
MMR_THRESHOLD      = 0.15
```

```python
score = (WEIGHT_KEYWORD_SIM * sim
       + WEIGHT_RECENCY * rec
       + WEIGHT_RELIABILITY * rel)
```

**MMR 多样性选择**（[retriever.py:37-58](../ai/retriever.py#L37-L58)）：候选与已选经验的最大相似度过高时降权，避免返回高度雷同的经验：

```python
for score, sim, exp in scored:
    if len(selected) >= top_k: break
    if not selected:
        selected.append(exp); continue
    max_sim = max(self._keyword_similarity(
        exp["intent"]["keywords"], s["intent"]["keywords"]) for s in selected)
    mmr = min(score + WEIGHT_DIVERSITY * (1 - max_sim), 1.0)
    if mmr > MMR_THRESHOLD:
        selected.append(exp)
```

> `retrieve` 故意不调 `update_usage`——使用统计由管线末尾统一处理，避免检索副作用。

```python
async def run_pipeline(user_desc, config, deps):
    stage_models = config.get("stage_models", {})
    model_stage1 = stage_models.get("stage1", model_name)  # 小模型省时
    model_stage2 = stage_models.get("stage2", model_name)  # 大模型保质量
    model_stage3 = stage_models.get("stage3", model_name)

    # Stage 1
    planner = ScenePlannerAgent(model_stage1, api_key, base_url, deps=deps)
    result1 = await planner.run(user_desc)
    blueprint_json = result1.output.model_dump_json()

    # Stage 2
    builder = JSONBuilderAgent(model_stage2, api_key, base_url, deps=deps)
    result2 = await builder.run(blueprint_json)
    scene_json_str = result2.output.model_dump_json()

    # Stage 3
    guard = QualityGuardAgent(model_stage3, api_key, base_url, deps=deps)
    result3 = await guard.run(scene_json_str)
    return result3.output   # ValidationReport
```

### 7.2 GUI 入口 AgentWorker（QThread + asyncio）

源码：[scripts/mapforge_app.py:1207](../scripts/mapforge_app.py#L1207)

**核心难题**：PydanticAI 的 `Agent.run()` 是协程，QThread.run() 是同步方法。解法——线程内创建独立 event loop 驱动协程，避免与 Qt 主循环冲突（[mapforge_app.py:1293-1297](../scripts/mapforge_app.py#L1293-L1297)）：

```python
loop = asyncio.new_event_loop()
asyncio.set_event_loop(loop)
result1 = loop.run_until_complete(planner.run(user_desc))
```

**信号机制**（[mapforge_app.py:1221-1228](../scripts/mapforge_app.py#L1221-L1228)）— 每阶段完成发信号到 UI 主线程，用户实时看到中间产物：

```python
stage0_done = pyqtSignal(str)       # 叙事扩写文本
stage1_done = pyqtSignal(str)       # 蓝图 JSON
stage2_done = pyqtSignal(str)       # 场景 JSON
stage3_done = pyqtSignal(str)       # 校验报告 JSON

```

**启动与信号连接**（[mapforge_app.py:2591-2623](../scripts/mapforge_app.py#L2591-L2623) `_start_pipeline`）：

```python

                           enable_enrichment=self._enable_enrich)
```

**懒加载 Agent 框架**（[mapforge_app.py:1275-1283](../scripts/mapforge_app.py#L1275-L1283)）— `pydantic_ai` 首次导入约 6 秒（连带 fastmcp/openai/mcp），延迟到用户实际运行流水线时再加载，GUI 启动无需等待；模块导入由 `sys.modules` 缓存，后续零开销。

### 7.3 Stage 0 跨线程人机同步（threading.Event）

**问题**：Stage 0 扩写后需用户在 GUI 编辑确认，QThread 必须阻塞等待，但不能卡死 Qt 主循环。

**解法**（[mapforge_app.py:1235,1327-1330](../scripts/mapforge_app.py#L1327-L1330)）— `threading.Event` 实现 QThread → GUI 主线程的跨线程同步：

```python
# AgentWorker.__init__
self._enrich_event = threading.Event()   # 跨线程同步原语

# Stage 0 完成后（AgentWorker 线程）
self.stage0_done.emit(narrative)
self._enrich_event.clear()
self._enrich_event.wait()                # 阻塞 QThread，GUI 完全不受影响
user_desc = self._enriched_text          # 用编辑后文本替换
```

```python
# GUI 主线程：用户点击"确认并继续"后（confirm_enrichment）
def confirm_enrichment(self, edited_text):
    self._enriched_text = edited_text
    self._enrich_event.set()             # 释放阻塞，AgentWorker 恢复
```

> `threading.Event.wait()` 不依赖 Qt 事件循环，QThread 阻塞期间 GUI 完全可响应——这是人机协作断点的关键技术。

## 八、关键工程设计点汇总

| 设计点 | 代码体现 | 作用 |
|--------|----------|------|
| **模板方法模式** | `AgentBase.build()` 固化流程 + 3 个抽象钩子 | 子类只填差异，消除重复 |
| **懒加载缓存** | `if self._agent is not None: return` | 同一智能体实例可多次 run 不重复构建 |
| **依赖注入** | `AgentDeps` dataclass + `agent.run(deps=)` | 工具从 `ctx.deps` 取后端，解耦组件与 LLM |
| **结构化输出** | `output_type=SceneJSON` 等 Pydantic 模型 | LLM 输出自动解析+校验，下游强类型使用 |
| **模型校验即反馈** | `PlacementConfig.validate_asset_nonempty` | Pydantic 校验失败 → PydanticAI 自动重试反馈 LLM |
| **工具=函数签名** | `@agent.tool` + 类型注解 + docstring | 签名即 API 文档，PydanticAI 自动转 JSON Schema |
| **核心函数/工具装饰分离** | `*_core` 函数 vs `@agent.tool` | 核心函数接纯 Python 对象，便于单元测试 mock |
| **程序化强制约束** | QualityGuard 闭包计数器 `_round_counter` | 用代码而非提示词强制 LLM 行为边界（防死循环） |
| **链式串行** | `run_pipeline` 硬编码阶段顺序 | 无 orchestrator，简单可靠 |
| **分级模型** | `stage_models` 配置字典 | 省 token / 保质量可分阶段调优 |
| **跨线程人机同步** | `threading.Event.wait()` + `confirm_enrichment()` | Stage 0 阻塞等用户确认，不卡 Qt 主循环 |
| **分层知识注入** | KnowledgePack L1/L2/L2.5/L3/L4 | 按意图动态组装 prompt，减少冗余上下文 |
| **模板智能裁剪** | `_trim_template` 保留骨架截断数组 | 超大模板不放弃，裁剪后注入保结构参考 |
| **FTS5 加速检索** | ExperienceBank `experiences_fts` 虚拟表 | O(k) 筛选候选再精确 Jaccard，避免全表扫描 |
| **四因子+MMR** | ExperienceRetriever 0.65/0.15/0.20/0.10 | 平衡相似度/时效/可靠/多样性 |
| **懒加载框架** | Agent 框架延迟到运行时导入 | GUI 启动不等待 6 秒框架加载 |
| **环境变量密钥** | `${VAR_NAME}` 解析 | 避免密钥明文存储配置文件 |
| **资源管理** | `finally` 关闭 SQLite/event loop | 异常时不泄漏连接 |

## 九、数据流契约与阶段间传递

### 9.1 序列化传递协议

每阶段输出统一用 `model_dump_json()` 序列化为字符串喂给下一阶段：

```
Stage 0 → Stage 1: 纯文本字符串（用户编辑后）
Stage 1 → Stage 2: blueprint.model_dump_json()  (SceneBlueprint JSON)
Stage 2 → Stage 3: scene_json.model_dump_json() (SceneJSON JSON)
Stage 3 → 输出:    report.scene (dict，可直接传 build_scene.py)
```

### 9.2 验证闭环

```
LLM 输出
  → Pydantic 模型解析（output_type）
    → model_validator 自动校验（如 asset 非空）
      → 失败 → PydanticAI retries=3 反馈 LLM 重试
        → 成功 → 进入下一阶段
Stage 3 再做：
  → validate_scene_core（字段完整性）
  → validate_assets_core（资产磁盘存在性）
    → 有错 → LLM 修复（可调 search_assets）→ 重验（闭包计数器限 3 轮）
```

### 9.3 校验工具复用既有脚本

[validation_tools.py](../ai/tools/validation_tools.py) 不重复造轮子：
- `validate_scene_core` 复用 [scripts/validate_scene_json.py](../scripts/validate_scene_json.py) 的 `validate_scene`
- `validate_assets_core` 复用 [tools/check/validate_scene_assets.py](../tools/check/validate_scene_assets.py)（用 importlib 按路径加载）
